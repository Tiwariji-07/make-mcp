# Product

## Register

product

## Users

API developers, platform engineers, security-conscious AI teams, and technical builders converting OpenAPI or Postman sources into MCP servers. They work in an inspection-and-configuration workflow: import a spec, understand what will be exposed, constrain it, test it, generate it, and connect it to a client without losing control of secrets or network behavior.

## Product Purpose

mcpmint turns API descriptions into deployable MCP servers while making the consequences visible before code leaves the browser. Success means a user can understand capability gaps, trust findings, outgoing requests, generated supply-chain artifacts, and installation steps without reading the generator source.

## Brand Personality

Precise, candid, protective. The product should feel like a well-built engineering workbench: dense when evidence matters, quiet when a decision is routine, and explicit whenever an action crosses a trust boundary.

## Anti-references

- Generic AI generator marketing that hides limitations behind celebratory copy.
- Security theater: unexplained scores, green shields without evidence, or warnings that cannot be acted on.
- Decorative glassmorphism, neon cyber-security styling, and dashboard chrome that competes with the work.
- Wizard flows that conceal state, silently rewrite user choices, or make recovery difficult.
- Card grids used as the default information architecture for every feature.

## Design Principles

1. **Show the evidence.** Every score, warning, diff, and readiness state must lead to the exact tool, parameter, construct, or generated artifact behind it.
2. **Safe defaults, visible escape hatches.** Local processing, read-only endpoint suggestions, authenticated remote presets, and atomic writes are defaults; advanced choices remain available with consequences explained.
3. **Preserve user intent across change.** Re-imports, regeneration, presets, and project updates must retain deliberate names, descriptions, filters, and security choices whenever their underlying endpoint still exists.
4. **Progressive depth.** The common path stays direct, while inspection, remediation, request simulation, and supply-chain evidence expand in place when needed.
5. **Make completion provable.** Downloads, installations, and client connections end with attestations or checks a user can retain and rerun.

## Accessibility & Inclusion

Meet WCAG 2.2 AA across dark and light themes. All workflows must be keyboard-complete, screen-reader named, usable at 320 CSS pixels without two-dimensional scrolling, and meaningful without color alone. Honor reduced motion and system theme preferences. Security and capability language must avoid unexplained jargon and include remediation steps.
